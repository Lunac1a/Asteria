关键设计
一实例一模型进程，一次只处理一个任务，不排队。与 Indexing 共享原有
worker_slot(1)，没有增加并发容量。FastEmbed 仅在子进程加载一次，沿用
当前模型、离线缓存、threads=2、query_embed(batch_size=16) 和内存限制。
父进程不加载模型，不向子进程传递数据库或 Provider 凭据。
Windows 原子 Job 绑定、不可继承 KILL_ON_JOB_CLOSE、原内存 Job 嵌套。
阻塞管道读写在专用 IPC 线程执行，调用方有 deadline；没有用户任务队列。
启动失败阻止应用启动。运行中失败返回 503，保持 Recovery Readiness 原状。
结束前确认实际模型、启动器、整个 Job 和 IPC 线程退出；确认失败则记录
DEGRADED、保留已占用 Slot，禁止再发任务。没有重启、重试或 Disposable 回退。

Remaining Limitations

仍是单 API 进程/单 Worker，不宣称 Asteria 支持多 Worker。
未实现 Queue、自动重启/重试、复杂取消、模型热更新、独立模型健康探针。
