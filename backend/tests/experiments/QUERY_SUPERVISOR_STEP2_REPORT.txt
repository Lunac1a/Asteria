Single-flight 与资源安全
Condition 锁保护 state/current worker/inflight。只有一个后台线程调用
factory/start/close，其他请求不能创建实例。初始化、IPC、进程清理均不
持有 Supervisor 锁；锁内的进程探测为 WaitForSingleObject(handle, 0)。
请求获得当前实例后设置 inflight，后台线程不会在请求执行中关闭该实例。
正常任务互斥仍为原 429；故障发现者原子切换 FAILED，恢复期间全部 503。

READY -> FAILED -> TERMINATING -> FAILED(backoff) -> STARTING -> READY。
终止时确认实际模型和启动器句柄、整个 Job ActiveProcesses=0、IPC 线程
退出，关闭资源后才释放已占用 Slot，然后才允许下一次实例创建。
清理失败 -> DEGRADED：保留旧实例/Job/占用记录，无重启，无自动清理循环。
初始启动失败仍阻止应用启动，不进入启动重试循环。

重启预算按应用生命周期累计，成功重启不重置。默认最多 3 次替代尝试，
PERSISTENT_QUERY_RESTART_LIMIT 范围 0–5。默认退避 1/2/4 秒；基础值由
PERSISTENT_QUERY_RESTART_BACKOFF_SECONDS 设置（0.1–30），指数退避上限
30 秒。关闭可以中断退避；关闭取消已预留尝试也计入预算。预算耗尽后
FAILED/exhausted=true，请求不能唤醒新一轮重启。修复环境后需操作者重启应用。
没有请求重试、请求队列、复杂取消、预算自动重置或运行时 reset 接口。

Remaining Limitations
仍限现有单 API 进程/单 Worker 部署、Windows 10+ Job Object 支持环境。
仅 Query Embedding 自动恢复；运行中故障不改变 Global Recovery Readiness。
不存在独立模型 HTTP 健康端点；Supervisor.snapshot() 提供内部状态。
未测试真实 TCP、生产 LLM、PostgreSQL 崩溃协议或长时间反复故障压测。
本轮未重做父进程 kill、内核不可终止进程或驱动故障测试。
启动/任务/关闭均有限超时，关闭会等待当前任务或初始化结束；不提供强行
取消正在初始化的 Python 线程。无法确认清理的实例始终保留所有权记录。
首次启动仍 fail-closed；DEGRADED 或预算耗尽需要操作者介入，没有自行
扩大到完整 Supervisor 管理系统。
