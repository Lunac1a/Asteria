设计变更
QueryWorkerSupervisor 使用可注入的 time.monotonic 时钟记录实际初始化尝试。
默认滚动 600 秒最多 3 次重启，连续 3 个失败恢复周期后 MANUAL_REQUIRED。
默认值待调优，未宣称最优。预算耗尽进入 COOLDOWN；期限到达后由唯一后台
生命周期线程主动恢复，经过 Backoff/初始化/READY，不依赖 Embedding 请求。
恢复期间 Embedding 立即 503；READY 忙时原 429 不变。
只有持续 READY 满整个窗口才清除连续失败历史，短暂 READY 不清除。
每个不稳定周期另限制 restart_limit 次尝试：防止慢失败初始化长于窗口时
不断过期而无限重启。冷却到最早时间戳过期；无时间戳时等待完整窗口。
初始化和清理仍在 Condition 锁外；请求不能创建 Worker。DEGRADED 与
MANUAL_REQUIRED 均不能靠时间过期解除，操作者需排查并重新启动应用。

Verified Observations
JSON：evidence/restart-policy-step25-03/result.json，passed=true。
1. 5 次跨窗口偶发故障均恢复 READY，没有永久耗尽预算。
2. 短期失败进入 COOLDOWN；推进期限后，无请求触发也只创建一次替代实例。
3. 3 个失败周期后 MANUAL_REQUIRED；再推进 10000 秒仍拒绝自动恢复。
4. 长于窗口的失败初始化同样在第 3 个周期停止。
5. DEGRADED 推进 10000 秒后仍保留 Job/Slot，未创建新实例。
6. 真实 Windows Job + FastEmbed：杀死模型 PID 33308，注入一次启动前失败，
   冷却后后台启动模型 PID 2796；恢复后 384 维向量与原 Disposable 完全一致，
   max_abs_difference=0。该实验使用加速可控时钟，不是等待真实 10 分钟。
7. 替代创建前旧 Job 的 3 个已捕获进程句柄全部确认退出；最终新旧共 6 个
   句柄退出、Supervisor 停止，临时模型副本目录移除。没有数据库或外部 Provider。

Remaining Limitations
不是长时间运行或故障率调参实验；可控时钟验证状态转换，不代表实际调度精度。
真实进程恢复仅一个受控场景；连续周期/慢初始化/DEGRADED 使用确定性测试替身。
本轮无数据库实验，不把 SQLite 回归推广为 PostgreSQL 并发证据。
已观察成员句柄保护当前已验证模型进程树，未穷举任意动态创建后又消失的子进程树。
仍仅支持当前 Windows/单 API Worker；没有 Queue、请求重试、复杂取消或管理重置接口。
全局 Recovery Readiness 未因运行中 Embedding 故障改变；默认仍走 Disposable。
